# Sprint 3 GPU relay

Poll configured stream folders for capture-request.json, validate immutable refs and supported shots, retain each distinct request by hash and run the GPU capture tool. Never run a local browser. Durable request records prevent duplicate launches after restart; failures remain evidence and can be retried by changing the request. Upload a tar of results plus feedback.md for remote agents to download and inspect. Automated feedback reports transport/machine evidence only; artistic verdict requires a person/agent to read PNGs. Default concurrency two to keep local RAM light; polling and processing are bounded by the sprint hard stop.

Matched A/B relay supports FOX_GAIT_CAPTURE_SCRIPT pointing at a frozen exact capture module. This prevents unrelated route/editorial tooling edits from changing the gait tool hash between baseline and candidate. Imported shot dependencies stay supplied by the repository; preserve the gait script and configuration alongside comparisons.

Each request extracts only tools/ from the exact requested commit into a temporary directory. Modal builds that capture harness against the same pinned game commit, so new stream-specific shots (e.g. hub) are available before main integration. For a standalone matched gait request only, replace its capture module with the frozen baseline module. Tool hash in metadata records the actual module. No additional game checkout, browser or npm install runs locally.

The live roster can be changed in OUT/streams.txt (whitespace or comma separated) without restarting. SIGTERM/SIGINT stops polling and cancels queued work while allowing running captures to finish. followup_shots and an also object enqueue the requested companion captures. During the r2 handover two existing legacy captures finish while the new two-client relay starts; this transient four-GPU overlap uses no local browsers and avoids canceling durable evidence.
